# Shittim Bookish V4 · 回滚方案

本文给出把仓库从「已接入 V4」安全回到「接入前 dev 基线」的步骤，以及故障
分级处置。V4 改动全部落在前端 `src/components` 与后端
`src/modules/external-providers/infrastructure`，没有迁移文件、没有数据库
schema 变更、没有 worker 结构性变更，因此回滚是低风险纯代码回退。

## 前置事实

- 接入基线：`dev` @ `8c9d70470631233953797bb62ff5c73acc3e1d84`
- V4 提交分支：`feature/shittim-v4`
- 变更未 push（本次按要求本地验证并分段提交，暂不推送远端）。

## 方案 A：直接回退提交（推荐，未 push 时最干净）

```bash
cd /path/to/zhiling

# 回到 dev（或你的备份基线）
git checkout dev
git branch -f shittim-v4-backup feature/shittim-v4   # 保留现场备份
git branch -D feature/shittim-v4                     # 可先不删，仅在确认后

# 若 dev 已有其它提交，则反向应用本次分支的补丁：
# git checkout dev
# git revert --no-commit <最新提交>..<最早提交>   # 按顺序回滚，或直接 git apply -R
```

回退后确认工作区与 dev 完全一致：

```bash
git status --porcelain          # 为空
git diff dev --stat             # 为空
pnpm typecheck && pnpm test:contracts && pnpm build
```

## 方案 B：按文件回退（局部回退某一层）

后端适配层单独回退：

```bash
git checkout dev -- \
  src/modules/external-providers/infrastructure/runtime.ts \
  src/modules/external-providers/infrastructure/wire-io.ts \
  src/modules/external-providers/infrastructure/model-format.ts \
  src/modules/external-providers/infrastructure/runtime.contract.test.ts
```

前端书卷/流程单独回退：把 `src/components/`（尤其 home-page、generation-page、
learning-workspace 与 shittim-immersive/）整目录还原到 dev 版本：

```bash
git checkout dev -- src/components/home-page.tsx src/components/generation-page.tsx \
  src/components/learning-workspace.tsx src/components/shittim-immersive
```

移除新增素材（可选）：`git rm public/shittim/anon-easter.webp`（不影响功能，
仅让彩蛋回到“引用图缺失则显示 Anon 字样”的旧行为——但旧版 bookish-chrome 已
被 V4 替换，若只回退页面文件请保持一致）。

## 故障分级处置

| 现象 | 处置 |
| --- | --- |
| 本地检查失败（format/lint/typecheck/build） | 按报错修正后重跑 `pnpm check`；不要带错提交 |
| 集成/E2E 失败且确认为本次引入 | 对比基线（见仓库 `docs/验证结果.md` 的同款 3 项环境性失败），确认非本次引入后可继续 |
| 线上生成质量回退（模型拒答/JSON 异常） | V4 刻意未恢复 `structure` 阶段 excerpt（依据 8d17bfa 生产修复）。若确需尝试，单独评估该单点，勿整体回滚 |
| 视觉/布局回归（标题重叠、按钮遮挡） | 浏览器验收清单重跑；问题集中在 scenes.module.css 单文件，可先回退该文件 |
| 其它意外 | 执行方案 A 全量回退到 dev，确认功能恢复后再逐段重试 |

## 数据库与部署影响

- 无 schema 迁移；无新表/新列/新索引。
- 无 worker 或队列结构变化；生成 worker 仍按原逻辑运行。
- 部署回滚只需回退代码并重启应用（Next.js build + worker），无需动数据。
