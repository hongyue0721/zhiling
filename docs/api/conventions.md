# API 约定

> 状态：基础错误信封、资源字段和 SSE 传输约定均已冻结；各接口的领域错误码以 OpenAPI 与对应接口说明为准。

## 契约原则

- OpenAPI 是已发布 HTTP 契约的机器可读事实源；Markdown 只解释设计原因。
- 所有外部输入在接口边界执行运行时校验，TypeScript 类型不能替代校验。
- 接口层只处理协议、身份上下文、校验和响应映射，不承载领域规则。
- 除注册和登录接口外，所有 HTTP 与 SSE 业务接口必须验证 Session；邮箱验证和
  显式重发验证邮件仅在 `EMAIL_VERIFICATION_ENABLED=true` 时登记为未登录例外。
- 业务接口从 Session 取得身份，不接受客户端传入用户 ID 进行授权。
- 破坏性变更不能静默覆盖旧契约，必须登记支持范围、迁移方式和移除条件。

## 资源与响应

- 对外标识使用不暴露数据库顺序和内部关系的稳定 ID；
- 时间使用带时区的 ISO 8601 表示，数据库保存规则另行决策；
- 枚举值必须封闭并在契约中列出，未知值不能自动映射到“其他”；
- 可空、缺失和空集合表达不同语义，schema 必须显式区分；
- 服务端内部模型、数据库行和 API DTO 不能共用同一未经转换的对象。

## 错误模型

业务 HTTP 错误统一遵循 [错误模型](error-model.md)和 ADR-0009。基础信封表达：

- 稳定、可编程处理的错误码；
- 面向用户或调用方的安全说明；
- 用于日志关联而不泄露内部细节的请求 ID；
- 仅在确实可重试时提供的重试提示；
- 字段校验错误的精确位置。

内部异常、第三方响应正文和堆栈不得直接返回客户端。每个接口仍必须列出实际可能出现的领域错误码，不能把统一结构当作万能错误语义。

## SSE 约定（已冻结）

生成进度事件使用以下封闭类型：

- `snapshot`：当前账户有权读取的完整任务快照；初次连接、历史不可用或任务已经处于终态时使用；
- `progress`：已确认的阶段状态变化；
- `succeeded`：任务成功终态；
- `failed`：任务失败终态，失败分类和 `retryable` 只来自当前账户有权读取的快照。

每条事件都包含协议版本（当前为 `"1"`）、任务标识、单调递增的 `sequence`、发生时间和安全 `data`；SSE `id` 与 JSON 中的 `sequence` 相同。事件只报告已确认的状态、阶段、正式结果标识和稳定失败分类，不能发送候选节点、题目、来源正文或第三方错误正文。终态事件发送后关闭连接；终态快照中的 `result` 或 `failure` 仍按当前账户授权投影。

客户端以 `Last-Event-ID` 携带最后收到的序号重连。服务端在历史仍保留时只重放更大序号的事件；历史不可用时先发送当前完整授权快照，再发送可用的新事件。晚于任务当前序列的游标返回 `400 out_of_range`，不建立无限等待的流。非终态连接每 15 秒发送 `: keep-alive` 注释；重连必须重新验证 Session 与任务参与关系。
