# 访问控制矩阵

> 状态：身份认证、精选读取、学习关系地图读取、学习验证、学习进度、私人报告与生成参与关系已落地；用户闭环和上线门禁仍按后续工作包推进。

## 基本原则

- 认证只证明当前会话对应哪个正式账户，不能代替资源授权；
- 除注册、登录、邮箱验证和显式重发验证邮件外，所有页面、HTTP 接口和 SSE 订阅都默认拒绝未认证访问；一期不提供密码恢复入口；
- 页面重定向只改善体验，Server Component、Route Handler、Server Action 和 SSE 必须各自在服务端验证 Session、`emailVerified=true` 及资源权限；
- 仅知道资源 ID 或任务 ID 不能自动获得访问权；
- 受保护内容不得进入未区分账户的公开静态缓存或 CDN 缓存。

服务端入口统一通过 `identity.resolve(headers)` 或 `identity.require(headers)` 取得最小正式身份；产品页面尚未实现，后续页面与业务传输入口必须在自身服务端边界调用该能力，不能只依赖前端重定向。

## 已落地的精选读取边界

- `GET /api/featured-learning-maps` 与 `GET /api/featured-learning-maps/{mapId}` 分别提供精选目录和当前精选版本详情；
- 两个入口在各自 Route Handler 调用统一正式身份能力，未登录或邮箱未验证统一返回 `401 authentication_required`；
- 详情只解析 ADR-0011 的精选指针；不存在、草稿、非精选和不可见状态统一返回 `404 resource_not_found`；
- 当前精选内容允许任意正式账户读取，不接受客户端用户 ID，也不据此开放自定义地图；
- 成功与错误响应均使用 `Cache-Control: private, no-store`，不能进入未区分账户的公开静态缓存或 CDN。

## 已落地的学习关系地图读取

- `learning_relationship` 唯一绑定一个正式账户和一个不可变已发布地图版本；
- `GET /api/learning-relationships/{learningRelationshipId}/map` 只使用 Session 账户与路径中的关系 ID 查询，不接受客户端声明账户；
- 关系不存在、属于其他账户或未绑定已发布版本时统一返回 `404 resource_not_found`；
- 建立学习关系是供生成成功和缓存命中调用的服务端能力，没有凭地图 ID 加入或分享的 HTTP 入口。

## 已落地的学习验证与进度边界

- `GET/POST /api/learning-relationships/{learningRelationshipId}/nodes/{nodeId}/assessment` 和 `GET /api/learning-relationships/{learningRelationshipId}/progress` 均在 Route Handler 先调用 `identity.require(request.headers)`。
- 验证与进度应用只接受服务端解析的 `userId`，再通过学习目录公开关系读取契约校验关系归属、节点存在和固定地图版本；关系 ID 不授予其他账户访问权。
- 题目集发布属于服务端应用能力，不提供客户端发布入口。已发布题目集绑定地图版本，题目来源必须属于节点来源。
- 判题事务按关系行串行化幂等检查、不可变尝试和进度最佳值更新；客户端不能提交完成状态或最佳分数。
- 题面和进度/历史摘要响应使用 `Cache-Control: private, no-store`；其他账户、失效关系、无题目集或不存在节点统一 `404 resource_not_found`，不暴露资源存在性。

## 已落地的生成任务复用边界

ADR-0014 将复用执行和共享授权分开，生成请求、状态查询与 SSE 已按该边界实现：

- 每个合法请求账户登记唯一任务参与关系；
- 后续账户只有主动提交相同生成身份后，才能在创建或复用任务的事务中成为参与者；
- SSE 建连和重连同时校验 Session 与任务参与关系；
- 任务成功或命中缓存后，各参与账户分别建立自己的学习关系；
- 缓存地图内容可以复用，答题、进度和报告仍归各自账户；
- 自定义地图正文只允许具有对应学习关系的账户读取，不提供凭地图 ID 加入或分享；
- 直接猜中任务 ID 或地图 ID 的其他登录账户统一得到不暴露存在性的 `404 resource_not_found`。

## 已落地的私人报告边界

`GET /api/learning-relationships/{learningRelationshipId}/report` 只允许当前正式账户读取所属学习关系的服务端投影。Route Handler 先通过 `identity.require` 验证 Session，再把服务端 `userId` 和关系 ID 交给报告公开入口；学习目录与学习进度读取各自再次按账户校验关系归属。

- 报告固定使用关系绑定的 `versionId`、`questionSetId` 以及该版本的节点、来源、观点、最佳成绩、完成状态和不可变尝试摘要；
- `weakNodes` 仅包含已作答但未完成节点；`encounteredViewpoints` 仅包含有不可变尝试节点的观点；`nextSteps` 仅包含所有直接前置已完成的未完成节点，并将已作答节点排在未作答节点之前；
- 返回 DTO 不包含用户资料、Session、答案、原始尝试数组或 `attemptId`，成功和失败响应均使用 `Cache-Control: private, no-store`；
- 关系不存在和错误账户统一返回 `404 resource_not_found`，报告没有独立存储副本、分享快照、分享令牌或跨账户读取入口。

## 一期分享边界

ADR-0012 已取消一期分享能力。未来若重新引入分享，必须通过新的 ADR、数据模型和授权测试显式建立，不能把报告 ID 或地图 ID 当作隐式分享凭据。

## 实现验证要求

- 对矩阵中的每一行提供未登录、错误账户和合法账户测试；
- 会话过期后，新的 HTTP 请求和 SSE 重连必须重新认证；
- 错误账户读取自定义任务、地图、进度或报告时不得暴露资源是否存在；
- 日志记录拒绝类别和关联 ID，不记录会话令牌或受保护正文；
- OpenAPI 中声明会话安全方案，并区分未认证与无权限响应。
