# ADR-0004：地图生成状态机与原子发布

- 状态：Accepted
- 日期：2026-09-02
- 决策者：哥哥（鸿岳）

## 背景

地图生成包含缓存查询、模型规划、多次知乎搜索、结构重建、观点提取、题目生成、完整校验和持久化。过程通过 SSE 报告进度，且相同生成身份的并发请求需要合并。

若只以一个长请求和若干临时布尔值表示过程，断线、超时、重复请求和发布失败会产生无法判断或半完成的状态。

## 决策

采用持久化生成任务和单向状态机表达流程，状态集合及语义见 [`generation-pipeline.md`](../generation-pipeline.md)。

- 一个生成身份在同一时刻最多有一个有效任务；
- 只有持有有效数据库租约的 Worker 可以推进状态，阶段转换必须校验当前状态；
- 一期部署在自管 VPS 的 Docker 环境中。Next.js Web 与生成 Worker 使用同一代码库和镜像、作为独立进程运行，共用 PostgreSQL，不拆分独立业务服务；
- Worker 通过 PostgreSQL 原子领取任务。租约有效期 60 秒，每 15 秒续租；执行者失联后，其他 Worker 从最后一个已完成的持久化阶段接管；
- 每个阶段的输入和完成事实必须持久化，外部副作用使用稳定幂等身份。`publishing` 只能在单个事务中执行，事务失败不留下可读地图，并从已验证候选重新发布；
- SSE 是任务状态投影，不是唯一事实来源。每个任务事件使用单调递增序号；客户端以 `Last-Event-ID` 重连，服务端重放仍保留的后续事件；事件不可重放时先返回当前完整快照，再继续推送新事件；
- Session 失效或账户不具有 ADR-0014 定义的任务参与关系时，初次订阅和重连都必须失败；
- 单个任务硬时限为 10 分钟。瞬时网络失败、超时、限流及供应商 `5xx` 每个外部阶段最多自动重试 2 次并使用指数退避；无效主题、材料不足、候选校验失败和授权失败不自动重试；
- 外部请求的单次超时由 #6 冻结的供应商契约确定，但不得超过任务剩余时限；纯数据库或本地校验步骤单次执行上限为 30 秒；
- 成功结果或可复用缓存都以 `succeeded` 终止；失败保存稳定错误类别，第三方详情只进入受控日志；
- 完整地图在最终校验后通过事务原子发布，只有 `succeeded` 任务关联的正式版本可以建立用户学习关系。

## 理由

持久化状态使 HTTP 请求、SSE 连接和实际执行生命周期解耦，并为并发合并、恢复、监控和明确失败提供统一事实源。

## 替代方案

- 只在 SSE 连接内执行：断线与运行状态耦合，难以可靠恢复。
- 将每个中间节点立即写成正式数据：用户可能读取证据不完整的地图。
- 使用进程内互斥合并请求：多实例部署时不能保证唯一性。

## 影响

- 数据库需要任务状态、生成身份、版本、阶段、错误、事件序号、执行租约和参与关系；
- Web 与 Worker 可以独立重启和扩容，但一期 VPS、反向代理、PostgreSQL 备份、系统更新、磁盘和进程监控由项目运维负责；
- 发布事务要同时保证地图图结构、证据关系和正式版本状态的可见性；
- 客户端可以按事件序号重连，并在事件历史不可用时以任务快照恢复；
- D1 必须实现失效租约接管、阶段幂等和明确的可重试错误分类，不能依赖进程内锁或 SSE 连接存活；
- 若未来迁移到 Serverless 或外部任务平台，必须重新评审执行时限、租约所有者和 SSE 拓扑，不能假定本决策自动适用。

## 迁移与验证

实现时通过状态转换单元测试、相同生成身份并发集成测试、Worker 在各持久化阶段中断后的租约接管测试、SSE 断线重连与快照恢复测试、十分钟总时限测试，以及发布事务故障测试验证。故障测试必须证明未校验候选和发布失败事务不会成为可读地图。

目标部署以自管 VPS Docker 为基线；部署清单、反向代理的 SSE 缓冲关闭、PostgreSQL 持久卷与备份恢复演练在工作包 D1/F 中交付。供应商单次请求超时在 #6 取得真实接口契约后写入适配器配置和运行文档。
