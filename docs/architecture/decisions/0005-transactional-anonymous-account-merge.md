# ADR-0005：匿名账户数据采用事务性幂等合并

- 状态：Proposed
- 日期：2026-09-02
- 决策者：待哥哥评审冲突规则

## 背景

匿名学习者能够生成地图、答题和保存进度。注册或登录后，这些记录需要合并到正式账户。匿名身份与正式身份可能已经学习同一地图，甚至存在不同进度和多次答题。

只修改外键或按记录覆盖会造成重复学习关系、丢失答题历史或完成状态倒退。

## 决策

账户合并作为独立应用用例，在单个数据库事务内完成，并使用稳定幂等键防止重试产生重复结果。

已确认原则：

- 合并来源必须是当前 Session 对应的匿名身份；
- 合并目标必须是完成认证的正式身份；
- 答题尝试作为历史事实保留，不能改写成另一身份的伪造尝试；
- 每个地图最终只保留一个目标学习关系；
- 合并完成后，匿名身份不能继续写入已迁移的数据；
- 任一实体合并失败则整体回滚，不能产生部分成功。

以下冲突策略尚待哥哥确认，接受 ADR 前不得由代码自行选择：

| 冲突 | 候选策略 | 需要确认的问题 |
| --- | --- | --- |
| 双方已加入同一地图 | 合并为目标账户的一条关系 | 加入时间和最近访问时间如何取值 |
| 同一节点有不同分数 | 保留全部尝试并重新推导最佳成绩 | 完成状态是否只看最高分 |
| 一方完成、一方未完成 | 根据合并后尝试重新推导 | 是否存在人工完成或特殊状态 |
| 同时发生新作答 | 对学习关系加锁并按提交顺序写入 | 可接受的锁粒度与等待时间 |
| 匿名身份已被合并 | 返回原合并结果 | 是否允许改合并到另一个正式账户 |

## 理由

该方案从业务事实重新计算派生状态，避免用简单覆盖掩盖冲突，并使认证回调重试保持安全。

## 替代方案

- 直接将所有匿名行的用户 ID 改为正式用户：遇到唯一约束冲突时无法保持语义。
- 正式账户记录始终获胜：会静默丢失匿名学习成果。
- 匿名记录始终获胜：可能使正式账户进度倒退。

## 影响

- 需要明确学习关系、答题尝试和进度投影的所有权；
- Better Auth 合并生命周期必须通过真实版本文档验证；
- 需要并发控制、幂等记录和安全审计；
- 冲突规则确认前不能完成该用例实现。

## 迁移与验证

接受前逐项填写冲突表。实现后测试首次合并、重复回调、双方重复地图、不同成绩、并发作答、事务中途失败和越权合并。
