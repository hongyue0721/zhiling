# ADR-0011：不可变地图版本与精选指针

- 状态：Accepted
- 日期：2026-09-02
- 决策者：项目维护者

## 背景

学习地图会被多个账户复用，并承载节点进度、答题记录和报告。精选地图还需要在人工复核后更新内容。若重新发布直接覆盖原节点、来源或观点，既有学习记录会失去当时的内容语境；若外部只暴露版本 ID，则精选主题缺少稳定身份，前端和后续学习关系无法区分“同一主题”与“同一版内容”。

哥哥已确认采用“不可变版本 + 精选指针”：地图主题保持稳定身份，每次发布形成新的不可变版本，精选目录显式指向当前发布版本。

## 决策

- `mapId` 标识稳定的学习地图主题，不标识某次生成或发布结果；
- `versionId` 标识一次完整、不可变的地图内容版本，节点、先修关系、来源与观点投影均归属于该版本；
- 版本只有在全部领域校验通过并完成原子持久化后才能进入已发布状态；草稿、失败结果和关系不完整的版本不得被读取接口返回；
- 精选目录通过独立指针关联一个稳定 `mapId` 和它当前的已发布 `versionId`，并保存明确的精选排序事实；
- 重新发布创建新版本并原子切换精选指针，不覆盖旧版本；
- 后续用户学习关系必须绑定明确的 `versionId`。精选指针切换不会隐式迁移既有学习关系、进度、答题记录或报告；
- 精选详情接口按 `mapId` 解析当前精选指针，同时在响应中返回实际 `versionId`，使客户端能够识别内容切换；
- 未列入精选、未发布或不存在的地图在精选读取边界统一按资源不存在处理，不泄露内部状态。

本决策不确定地图节点的展示排序、允许的分支宽度、旧版本保留期限或既有学习关系的显式升级流程。这些规则在相应工作包出现真实需求时另行确认。

## 理由

稳定主题身份便于目录、链接和精选运营引用同一学习方向；不可变版本让进度、答题与报告始终可以回到其原始内容。显式精选指针把“当前推荐哪一版”建模为可审计事实，而不是依赖时间排序或查询偶然结果。

读取响应同时返回 `mapId` 与 `versionId`，前端可以用前者路由和识别主题，用后者判断当前展示的内容版本，无需猜测发布时间或比较正文。

## 替代方案

- **原地图就地更新**：表结构简单，但旧进度和答题结果会被新正文重新解释，破坏历史一致性；
- **稳定 `mapId` 永远隐式解析最新版本**：读取方便，但若不返回实际版本，缓存、学习关系和问题定位无法确定所见内容；
- **每次发布都创建新的独立地图 ID**：内容不可变，但失去主题连续性，精选链接和学习统计被人为拆散。

## 影响

### 正向影响

- 旧学习关系能够继续绑定原版本，历史事实不会随精选更新漂移；
- 精选切换和回滚只需变更指针，不修改已发布正文；
- 后续生成缓存、题目版本和结课报告可以引用明确版本；
- 读取接口和客户端缓存具有可观察的版本身份。

### 代价与风险

- 数据模型需要区分地图主题、地图版本和精选指针；
- 发布事务必须保证完整版本先落库、发布状态后成立、精选指针最后切换；
- 旧版本保留和清理不能只按“非当前精选”判断，必须考虑学习关系、题目和报告引用；
- 未来若允许用户主动升级学习版本，需要独立业务规则和迁移记录，不能静默改写关系。

## 迁移与验证

1. 建立稳定地图、不可变版本、节点、先修关系、来源证据和精选指针表；
2. 发布服务先校验 5–7 个节点、同版本引用、图无环及来源证据完整性，再在事务中写入并切换精选指针；
3. 读取测试证明草稿、非精选和不存在的地图不可见；
4. 集成测试连续发布两个版本，证明精选读取切换到新 `versionId`，旧版本仍存在且内容未被覆盖；
5. OpenAPI 与前端协作文档明确 `mapId`、`versionId` 和缓存更新语义。
