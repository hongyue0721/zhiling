# ADR-0014：生成参与者与私有自定义地图授权

- 状态：Accepted
- 日期：2026-09-02
- 决策者：哥哥（鸿岳）

## 背景

相同规范化主题和生成版本应复用缓存与并发任务，但执行复用不能自动扩张账户权限。哥哥已确认一期不提供分享能力，因此其他登录账户仅知道任务 ID、地图 ID 或他人生成的主题，不应取得任务状态或自定义地图正文。

## 决策

### 任务参与关系

- 每个生成任务维护显式、唯一的账户参与关系；创建请求的正式账户在创建或复用任务的同一事务中成为参与者；
- 后续账户主动提交相同生成身份时，可以在同一事务中加入尚未终止的复用任务；加入前不具有任务访问权；
- 任务状态、SSE、阶段、稳定错误类别和重连快照只允许参与者读取；仅猜中任务 ID 的其他账户统一得到不暴露资源存在性的 `404 resource_not_found`；
- 第三方响应、内部异常和其他参与者身份永不进入任务响应。

### 成功地图与缓存

- 生成缓存和不可变地图版本是可跨账户复用的内容事实，不复制整张地图；
- 每个合法请求账户在任务成功或命中缓存时分别建立自己的学习关系，答题、进度和报告始终按账户隔离；
- 自定义地图正文只允许拥有该版本学习关系的账户读取；一期不提供凭地图 ID 加入、链接分享或把访问权授予其他账户的入口；
- 同主题的另一个账户必须通过自己的生成请求取得访问权。缓存命中可以立即复用既有正式版本，但仍须原子建立该账户的学习关系；
- 精选地图继续遵循 ADR-0011 的精选指针和任意正式账户读取规则，不受本 ADR 的自定义地图限制。

## 理由

该方案将内容复用、任务协作和用户授权拆开：系统保留跨账户缓存收益，用户看不到未主动请求的自定义主题，也不存在隐式分享。显式参与关系同时为 SSE 重连、错误隔离和后续审计提供稳定依据。

## 替代方案

- 自定义地图对任意登录账户凭 ID 开放：实现较简单，但会泄露其他账户生成的主题与正文。
- 只有最初发起者可以复用结果：隔离最强，但同主题后续请求无法安全命中缓存，与既定复用目标冲突。
- 提供加入码或分享链接：属于哥哥已明确取消的一期分享能力。

## 影响

- D1 需要任务参与关系、原子加入和租约恢复时的参与者授权；
- C2 自定义读取需要学习关系授权，不能复用精选读取的“任意登录账户”规则；
- 命中缓存也必须建立当前账户自己的学习关系，不能只返回共享地图 ID；
- F 的状态查询、SSE 重连和地图页面必须分别处理未认证与错误账户，但不得泄露资源是否存在。

## 迁移与验证

实现时覆盖创建者、后来同主题请求者、缓存命中账户、未登录账户和错误登录账户。并发加入必须只产生一条参与关系和一条学习关系；失败重试不得创建“看似成功但关系缺失”的数据。访问控制矩阵与 OpenAPI 在对应接口落地时同步固化这些响应。
