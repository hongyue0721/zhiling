# ADR-0003：使用适配器隔离外部供应商协议

- 状态：Accepted
- 日期：2026-09-02
- 决策依据：`PROJECT_GOAL.md` 第 6.4 节

## 背景

现行官方资料将知乎站内搜索与知乎直答提供为统一 HTTP 契约；当前没有独立的“正式接口/比赛接口”端点或 DTO。让业务层直接依赖这些第三方结构，会复制转换逻辑，并使供应商变化穿透整个应用。

## 决策

领域和应用层只依赖由业务定义的端口。知乎与模型集成分别由基础设施适配器实现，第三方 DTO 不得越过适配器边界。

知乎适配器负责鉴权、请求时间戳、字段转换、错误映射、规范化和必要字段过滤；模型适配器负责用途明确的生成调用、结构化输出解析和 schema 校验。

适配器只完成协议兼容和可信边界转换，不负责决定学习地图结构、来源是否足够、节点是否完成等领域规则。

## 理由

端口由业务需要定义，能够避免把供应商偶然字段变成核心模型，并让统一官方协议的字段、错误与版本变化只在适配边界内处理。若未来赛事另行提供独立契约，应新增兼容登记和适配器，不把它预先写成当前事实。

## 替代方案

- 在用例中直接调用 SDK：第三方错误、字段和重试策略会散落在业务代码中。
- 创建一个无类型的通用 HTTP 客户端作为兼容层：只复用了传输，无法封闭协议语义。
- 对不同接口复制完整业务流程：会产生平行语义和长期漂移。

## 影响

- 必须维护规范化模型与第三方原始样本之间的契约测试；
- 当前统一官方契约由同一适配边界承载；若未来出现独立赛事契约，新增兼容项或转换器，不改变业务端口；
- 未知枚举、缺失必要字段和第三方错误必须显式映射；
- 适配器版本参与地图缓存身份。

## 迁移与验证

编码前取得官方契约和脱敏真实样本，先定义端口能力与错误分类，再实现转换器。测试同时覆盖正常响应、字段缺失、未知类型、限流、认证失败和第三方暂时不可用。
