# ADR-0006：API 契约优先并显式管理兼容性

- 状态：Accepted
- 日期：2026-09-02
- 决策依据：项目协作要求

## 背景

知径将由多人分工开发，浏览器、服务端用例、SSE 进度和外部适配器之间都有独立演进的契约。若实现先行、文档事后补写，消费方只能猜测字段、错误和失败语义。

## 决策

- HTTP 接口以 `api/openapi.yaml` 为机器可读事实源；
- API 变更必须在实现合入前或同一变更中更新契约、示例和契约测试；
- SSE 事件同样需要版本、schema、示例和恢复语义；
- 内部模块通过显式应用契约协作，不共享数据库行或第三方 DTO；
- 每个兼容行为登记源目标、支持范围、失败语义、负责人和移除条件；
- 缺失事实、未知枚举和无效关系默认拒绝，除非契约明确允许默认或忽略。

## 理由

契约优先使并行成员能够在稳定边界上独立工作，并让文档、运行时校验和测试围绕同一语义演进。

## 替代方案

- 从实现代码自动推导全部契约：业务原因、兼容范围和失败语义容易缺失。
- 只维护 Markdown 示例：无法可靠执行校验和变更检测。
- 永久保持向后兼容：会积累无法移除的旧语义和不明确分支。

## 影响

- 接口设计成为功能工作的前置交付物；
- CI 需要校验 OpenAPI、schema 和破坏性变更；
- 兼容层需要指标或日志证明旧行为是否仍在使用；
- 紧急修复也不能跳过契约同步。

## 迁移与验证

工程骨架阶段增加契约校验和变更检查。第一个业务接口需同时交付 OpenAPI、运行时 schema、成功与失败示例以及实现契约测试。
