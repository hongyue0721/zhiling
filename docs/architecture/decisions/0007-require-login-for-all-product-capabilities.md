# ADR-0007：所有产品能力必须登录

- 状态：Accepted
- 日期：2026-09-02
- 决策者：哥哥（鸿岳）

## 背景

初始产品目标采用“先体验，后登录”，需要自动创建匿名会话，并在用户注册或登录时迁移学习关系、答题记录和进度。这引入了数据所有权变更、冲突合并、并发控制、幂等重试和账户错误绑定等业务复杂度。

项目重新确认产品边界：不提供匿名学习或未登录预览，所有产品能力必须登录后使用。

## 决策

- 未认证访问者只能进入注册和登录流程；
- 精选地图、自定义生成、地图节点、来源观点、答题、进度和报告均要求有效登录会话；
- HTTP 接口、SSE 订阅和产品页面使用一致的认证门禁；
- 使用 Better Auth 的 Email & Password 能力，不启用 Anonymous Plugin；
- 学习数据创建时直接归属于唯一正式账户；
- 服务端从 Session 取得身份，不接受客户端声明的用户 ID 作为授权依据。
- 一期分享范围已由 ADR-0012 取消；本 ADR 不再定义分享入口。

## 理由

该边界让身份和数据所有权从创建开始稳定，消除匿名账户合并及其冲突语义，降低事务、安全和测试复杂度。对所有读取和写入统一门禁，也比逐接口判断匿名能力更容易理解和验证。

## 替代方案

- 完整匿名学习后合并：用户进入成本较低，但产生复杂且高风险的数据迁移。
- 未登录只读精选内容：仍需要维护两套访问边界，与“所有产品能力必须登录”的明确要求不符。
- 未登录答题但不保存：形成无法恢复、无法计入进度的平行业务语义。

## 影响

- 新用户进入核心体验前必须先完成注册或登录；
- 结课报告只允许所属学习关系的账户读取，且一期不提供分享入口；
- 生成频率限制可以按正式账户实施；
- 不需要匿名会话、匿名数据表、合并事务和相关兼容层；
- 必须完整设计会话有效期、失败限制和认证可用性；邮箱验证与密码恢复是否纳入一期仍需单独确认。

## 迁移与验证

当前尚无应用代码和生产数据，无需数据迁移。实现阶段必须通过页面、HTTP 和 SSE 三类未登录访问测试，并验证登录后跨会话恢复学习数据。契约测试应确认只有经过明确登记的认证端点允许未登录访问。
