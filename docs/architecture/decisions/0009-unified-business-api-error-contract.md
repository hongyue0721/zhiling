# ADR-0009：统一业务 API 错误契约

- 状态：Accepted
- 日期：2026-09-02
- 决策者：项目架构基线

## 背景

身份、地图、生成、答题、进度和报告模块都会通过 HTTP 或 SSE 暴露失败状态。若每个模块自行设计错误对象，客户端会依赖字符串判断，第三方错误也可能穿透业务边界，兼容层将不断复制。

## 决策

所有非认证框架托管的业务 HTTP 接口使用统一错误信封：

```json
{
  "error": {
    "code": "invalid_request",
    "message": "请求内容不符合接口要求",
    "requestId": "req_01...",
    "issues": [
      {
        "path": "/topic",
        "code": "required",
        "message": "请输入学习主题"
      }
    ]
  }
}
```

- `code` 是稳定、机器可读的 `lower_snake_case` 标识；
- `message` 是安全的人类可读说明，客户端不得通过它判断逻辑；
- `requestId` 是服务端生成或验证后的日志关联标识；
- `issues` 仅用于可定位的输入问题，省略和空数组语义不同；
- `issues[].path` 使用 JSON Pointer；无法定位到字段的错误不伪造路径；
- HTTP 状态表达协议层类别，业务错误码表达具体语义；
- 可重试时间使用标准 `Retry-After` 响应头，不复制到 JSON 字段；
- 内部异常、堆栈、SQL、第三方响应、密钥和模型原始输出不得进入错误响应。

Better Auth 自身端点的错误格式属于框架契约。应用在认证边界将其映射为安全 UI 状态，但不伪装成由本 OpenAPI 管理的业务端点。

## 基础状态映射

| HTTP 状态 | 基础错误码 | 使用边界 |
| --- | --- | --- |
| 400 | `invalid_request` | 请求结构、参数或无法解析的输入错误 |
| 401 | `authentication_required` | 未建立有效正式账户 Session |
| 403 | `permission_denied` | 已认证但无权执行，且暴露资源存在性安全 |
| 404 | `resource_not_found` | 资源不存在，或为防止枚举而隐藏其存在性 |
| 409 | `state_conflict` | 幂等、版本或当前资源状态冲突 |
| 422 | 具体领域码 | 结构有效但违反明确业务规则 |
| 429 | `rate_limited` | 账户频率限制，必要时附 `Retry-After` |
| 500 | `internal_error` | 未预期内部错误，不暴露细节 |
| 503 | `dependency_unavailable` | 当前依赖不可用且业务无法继续 |

具体接口可以在保持相同状态语义的前提下增加稳定领域码。不同语义不得为了复用客户端分支而共用同一个模糊错误码。

## 理由

固定信封让客户端、日志、契约测试和模块适配器围绕稳定字段协作，同时保留接口定义具体业务码的扩展点。将重试时间放入标准响应头，避免两处事实不一致。

## 替代方案

- 只返回字符串：无法稳定处理、国际化或兼容演进。
- 直接返回 Zod、数据库或供应商错误：泄露内部实现并让客户端绑定第三方协议。
- 所有失败返回 200：破坏 HTTP 语义和中间设施的可观察性。
- 为所有错误都返回字段列表：会为非字段错误制造虚假位置。

## 影响

- OpenAPI 维护统一 schema 和可复用基础响应；
- 每个业务接口仍需声明实际可能返回的错误码，不能只引用一个万能错误；
- SSE 失败事件复用同一错误码命名，但其事件结构由 SSE 契约单独定义；
- 更改现有错误码属于兼容性变更，必须登记迁移和移除条件。

## 验证

首个业务接口必须提供成功、输入错误、未登录、无权限和内部错误契约测试。日志测试应证明 `requestId` 可关联且响应不包含内部异常或第三方原文。
