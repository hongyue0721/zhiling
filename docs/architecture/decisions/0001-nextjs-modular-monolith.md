# ADR-0001：采用 Next.js 全栈模块化单体

- 状态：Accepted
- 日期：2026-09-02
- 决策依据：`PROJECT_GOAL.md` 第 6.1 节

## 背景

一期主要能力是调用知乎与模型 API、组织结构化数据、持久化以及 Web 渲染。当前没有本地模型、音视频处理或大型离线任务等必须拆分独立服务的事实。

## 决策

采用 Next.js 15、React 和 TypeScript 构建全栈单体，并在单一部署单元内部维持明确的业务模块和分层边界。

- 接口层负责 HTTP/SSE、身份上下文、输入校验与 DTO 映射；
- 应用层编排用例、事务和跨模块公开契约；
- 领域层保存业务规则，不依赖 Next.js、数据库驱动或第三方 SDK；
- 基础设施层实现 PostgreSQL、知乎 API、模型 API 等端口。

一期不创建独立 Python 服务。若未来出现已经验证的独立伸缩、隔离或运行时需要，必须通过新的 ADR 重新划分部署边界。

## 理由

该选择与一期团队协作和交付范围匹配，避免在业务边界尚未经过实际验证时引入跨服务通信、分布式事务和多套部署设施，同时保留未来拆分所需的模块契约。

## 替代方案

- 前后端分离：增加跨仓库契约和部署成本，一期没有独立团队或运行边界需求。
- Next.js 加独立 Python 服务：当前工作负载不需要 Python 特有能力。
- 微服务：数据所有权和伸缩事实尚未成熟，过早拆分会放大一致性成本。

## 影响

- 构建、测试和部署入口可以统一；
- 模块隔离必须依赖目录约束、公开入口和测试，而不是网络边界；
- 长时生成任务由 ADR-0004 规定的同代码库独立 Worker 进程执行，不与 HTTP 或 SSE 连接生命周期绑定；
- 模块内部类型和数据库结构不得成为其他模块的隐式公共接口。

## 迁移与验证

工程骨架提供依赖边界检查，并以纵向切片验证接口层、应用层、领域层和基础设施层的依赖方向。生成任务按 ADR-0004 在自管 VPS Docker 环境运行；Web 与 Worker 使用同一模块和公开契约，不因进程拆分创建第二套业务服务边界。
