# 数据模型与一致性

> 本文件描述概念模型和已经落地的不变量；物理模式的事实源是 `src/platform/database/` 下的 Drizzle schema 与 `drizzle/` 迁移，尚未确认的领域字段仍需先完成契约评审。

每个核心实体需说明：

- 稳定身份和生命周期；
- 必填业务事实及其来源；
- 实体之间的基数、所有权和删除语义；
- 唯一性、不变量和事务边界；
- 并发冲突、幂等和重试规则；
- 审计、隐私、保留与清理要求。

缺失的必填事实必须显式失败。默认值仅可用于已确认的策略，不得用于伪造实体关系或完成状态。

## 已确认概念关系

- 学习地图包含 5–7 个地图节点；节点之间存在有向先修关系。
- 地图、节点和来源内容独立于用户；多个用户通过学习关系复用同一地图。
- 节点与来源是多对多关系，结构化观点通过观点来源关系保留一个或多个证据。
- 验证题属于节点；题目正文与服务端答案必须具有明确的输出隔离。
- 答题尝试不可被客户端改写；节点最佳成绩和完成状态按 ADR-0013 在服务端事务中推导，完成状态只能单向成立。
- 一期不创建分享快照、分享令牌或跨账户报告实体；结课报告只投影当前账户的学习事实。
- 生成任务关联规范化主题、流水线版本和来源适配器版本，并具有数据库租约、单调事件序号和账户参与关系；只有完整校验通过的地图才能发布。
- `learning_map` 表示稳定主题，`learning_map_version` 表示不可变内容版本；精选指针只关联同一地图的已发布版本；
- 精选重新发布创建新版本并切换指针，旧版本保留为后续学习关系和答题的稳定引用，详见 ADR-0011。

## 已落地的身份持久化

- `user` 以 Better Auth 生成的 ID 为稳定身份，邮箱唯一；只有有效 Session 对应的 `emailVerified=true` 用户才能转换为正式身份；
- `account` 保存 credential 账户及密码哈希，`issuer + accountId` 唯一；删除用户时账户级联删除；
- `session` 保存不透明唯一 Token、到期时间和账户关系；删除用户时级联删除，不启用客户端 Session 缓存；
- `verification` 保存一次性验证值及到期时间，按标识建立查询索引；
- `rateLimit` 以唯一 Key 保存窗口计数与最后请求时间，使多实例限流共享同一事实；
- 首版模式由 `drizzle/0000_identity_auth.sql` 建立。应用不得直接读取密码哈希、验证值或 Session Token 形成业务 DTO。

## 已落地的精选地图持久化

- 地图主题、版本、节点、先修边、来源、节点来源、观点和观点来源使用显式关系保存，不把嵌套 JSON 当作关系事实；
- 同版本复合外键阻止节点、先修边和观点跨版本关联；观点来源必须同时属于观点所在节点；
- 发布入口先在领域层校验 5–7 个节点、唯一引用、图无环、节点来源和观点证据，再在单个数据库事务中写入完整版本；
- 草稿写入完成后才能转换为已发布状态，精选指针最后切换；任何校验或事务失败都不能产生可读半成品；
- 读取投影只解析精选指针指向的已发布版本，并显式转换为公开 DTO，不把数据库行或内部发布状态返回给客户端；
- 物理模式由 `drizzle/0001_featured_learning_catalog.sql` 建立，并与 Drizzle schema 和迁移快照同步维护；
- 已发布版本不提供覆写入口。旧版本删除、保留期限及学习关系升级仍需后续独立决策。

## 已接受但待实现的不变量

- ADR-0013 固定等权计分、80% 完成阈值、无限重试、幂等提交、最佳成绩原子更新和题目版本隔离；
- ADR-0014 固定任务参与关系与自定义地图学习关系授权；生成缓存可以跨账户复用，任务状态、SSE、进度和报告不能跨账户读取；
- ADR-0012 取消一期分享能力，不得创建分享占位实体或把资源 ID 当作隐式分享入口。

## 仍需确认的不变量

- 再生成和缓存命中的规范化生成身份细节；
- 节点图先修关系变更规则；
- 用户删除、认证记录保留和审计规则；
- 来源去重身份、保留期限和第三方删除后的处理方式。
