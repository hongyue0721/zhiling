# 兼容性策略

兼容层用于隔离已知差异，不是无限期兜底。每个兼容项必须登记并测试。

## 兼容项要求

1. 明确源契约、目标契约和支持版本范围；
2. 定义转换前置条件、信息损失和失败语义；
3. 保留可观测指标，能够识别仍在使用旧行为的调用方；
4. 指定负责人、引入日期、废弃条件和计划移除版本；
5. 同时覆盖契约测试、转换测试和不支持场景测试。

不得：

- 静默吞掉未知字段、无效枚举或关系缺失；
- 用虚构默认值使不完整数据看起来成功；
- 在多个模块复制同一套兼容逻辑；
- 将某个调用方特例宣称为通用能力。

## 已知兼容边界候选

[知乎开放平台外部契约](../api/zhihu-open-platform.md)已经登记哥哥提供的黑客松资料包与官方 Skill 快照，但尚未取得本项目 Access Secret 下的脱敏真实响应样本，也未实现适配器。后续仍需确认：

- 公共 HTTP API 到统一来源模型的字段转换及未知枚举处理；
- 知乎 API 错误到内部可恢复、不可恢复、限流与配额错误的映射；
- 知乎直答或其他模型供应商结构化输出到领域候选结果的解析与校验；
- 数据库 schema、地图生成流水线和来源适配器的版本演进；
- SSE 事件协议在客户端版本变化时的支持范围。

对知乎接口不得凭字段名猜测实现。适配器契约必须依据官方资料、真实响应样本和契约测试共同确认。
