# 地图生成流程

> 状态：流程阶段、持久化状态机、VPS Docker Worker、租约恢复、缓存去重、原子发布和 SSE 重连已实现；生产成功调用仍需在部署环境使用受控 Access Secret 完成在线验收。

## 发布原则

地图生成是“候选内容逐步形成，完整校验后一次发布”的流程。阶段进度可以对用户可见，但未经校验的节点和题目不能伪装成正式结果。

## 已实现状态机

| 状态            | 含义                               | 可持久化正式地图 |
| --------------- | ---------------------------------- | ---------------- |
| `queued`        | 请求已接受，等待取得执行权         | 否               |
| `normalizing`   | 规范化主题并计算缓存身份           | 否               |
| `cache_lookup`  | 查询相同版本的可复用地图           | 否               |
| `planning`      | 生成 3–4 个粗粒度学习方向          | 否               |
| `searching`     | 按方向查询并整理真实知乎来源       | 否               |
| `structuring`   | 基于来源重建 5–7 个最终节点        | 否               |
| `supplementing` | 仅对材料不足节点补充一次搜索       | 否               |
| `extracting`    | 提取有来源关联的观点结构           | 否               |
| `assessing`     | 按两个节点一批生成有来源依据的客观题候选 | 否               |
| `validating`    | 校验图结构、来源、观点和题目不变量 | 否               |
| `publishing`    | 在事务边界内持久化完整地图         | 正在进行         |
| `succeeded`     | 已得到可读取地图，或命中有效缓存   | 是               |
| `failed`        | 已以明确错误终止                   | 否               |

除 `succeeded` 和 `failed` 外均为非终态。是否支持用户主动取消不在一期已确认范围内，不能先加入业务语义。

## 关键门禁

### 来源门禁

- 每个引用的来源 ID 必须来自本任务的规范化搜索结果；
- canonical URL、内容类型和必要展示字段通过知乎适配器校验；
- 适配器拒绝的数据不得由模型补造。

### 图结构门禁

- 节点数量符合 5–7 个的一期范围；
- 所有边端点存在、无自环且整体无环；
- 每个节点的学习目标、来源和题目达到确认后的最低要求。

### 证据门禁

- 每条结构化观点至少关联一个有效来源；
- 每道题目答案与解释关联节点已有来源；
- 模型返回的未知 ID、URL 或跨节点引用导致校验失败，而不是静默删除后继续发布。

## 缓存与并发

缓存身份至少由以下事实组成：

```text
normalizedTopic + pipelineVersion + sourceAdapterVersion + modelAdapterVersion
```

相同身份的并发生成请求共享一个任务或已发布结果，并通过数据库唯一约束和事务保证。每个主动请求账户按 ADR-0014 原子登记任务参与关系；复用执行不授予未参与账户读取权限。

### 出题批级缓存

`assessing` 不再把所有节点题目放进一次模型调用：节点按地图顺序每两个组成一批，最后一批可以少于两个。每批请求仍携带完整地图、观点和同一份来源上下文，只用 `targetNodeIds` 限定本批节点；成功后立刻写入 `generation_checkpoint`，键为 `stage=assessing` 与 `operationKey=assessing:batch-<index>`，且不转移任务状态。接管者按当前节点数重新计算批次数，复用已完成批并只补缺失批，随后将题目按地图节点顺序合并，再经过原有统一校验和发布。

批级 checkpoint 是任务执行中的细粒度恢复层；`generation_cache` 仍是完成发布后的任务级结果缓存。前者只保存当前任务的单批模型输出，后者保存可供相同生成身份复用的完整地图、题目集和版本关系，两者互不替代。

## 失败分类与重试

- `invalid_topic`：主题无法形成可执行学习目标，不重试；
- `source_unavailable`：知乎接口当前不可用，瞬时失败最多重试 2 次；
- `source_insufficient`：真实材料不足以形成合格地图，不重试；
- `model_unavailable`：模型接口当前不可用，瞬时失败最多重试 2 次；
- `model_output_invalid`：HTTP 成功但返回内容不是 JSON，或不满足当前用途的严格 schema/来源关系门禁；单个模型阶段最多 3 次总尝试（首次加最多 2 次自动恢复）；
- `candidate_invalid`：完整候选在最终本地质量校验中失败，不自动把它当成模型协议问题；
- `generation_timeout`：任务超过 10 分钟硬时限，不重试；
- `internal_failure`：不应向客户端泄露细节的系统错误。

模型协议恢复受任务级 PostgreSQL checkpoint 预算限制（当前上限 3 次额外恢复），避免每个模型阶段各自耗尽 3 次导致调用爆炸；预算和阶段 checkpoint 都随租约接管持久化。恢复请求逐次收敛来源数量、摘要长度和来源上下文字符目标；已被地图引用的真实 `sourceId` 以及每个规划方向至少一个已知来源优先保留，不能为了压缩输入而破坏关系。观点阶段只投影节点证据关系和来源标题/摘要；没有受证据支持的观点时，模型必须在 JSON 契约内返回空数组，而不是解释性正文。正常成功路径 planning、structuring、extracting 各调用一次，assessing 按批次每批调用一次。所有来源、节点、边、观点和题目关系校验仍在供应方边界及本地门禁执行，失败不会发布不完整地图。

每个外部阶段的网络/限流重试使用指数退避；单次来源与模型调用时限由服务端配置显式提供，并受任务剩余时限约束。稳定错误码、阶段和可重试性由服务端产生，第三方正文不进入 HTTP 或 SSE。

## 恢复与可观察性

- Worker 使用 PostgreSQL 任务租约：60 秒有效期、15 秒心跳，租约失效后由其他 Worker 接管；
- 每个阶段持久化输入和完成事实；接管者从最后一个已完成阶段继续，外部副作用必须具有稳定幂等身份；
- 任务事件按任务内单调序号持久化；SSE 使用 `Last-Event-ID` 重放，历史不可用时先返回完整任务快照；
- 初次连接和每次重连都重新验证 Session 与任务参与关系；
- 非终态事件显示服务端真实离散阶段、每个搜索方向/补充节点的完成计数、assessing 批次 `n/total`、模型 `n/3`、自动恢复预算和已复用 checkpoint 阶段；不生成百分比或 ETA；
- 单个任务硬时限为 10 分钟，本地校验或数据库步骤单次执行上限为 30 秒；
- `publishing` 在单事务内执行；失败事务不产生正式版本，接管或重试从已验证候选重新发布；
- 日志和指标记录任务关联 ID、阶段、耗时、重试次数和稳定失败类别，不记录供应商敏感正文或其他参与者身份。
