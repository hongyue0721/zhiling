# 安全边界

> 状态：身份认证、生成参与关系、自定义地图授权、题目计分、学习进度和私人报告边界及业务入口均已实现；用户闭环和持续上线门禁仍按后续工作包推进。

## 身份与授权

- 用户 ID 只从服务端 Session 解析，写接口不得信任请求体、查询参数或请求头中的用户 ID。
- 所有资源写操作同时校验身份、资源所有权和资源当前状态。
- 除注册、登录、邮箱验证和显式重发验证邮件外，所有页面、HTTP 接口和 SSE 订阅默认拒绝未认证访问。
- 系统不创建匿名学习身份，不提供匿名数据向正式账户迁移的隐式入口。
- 知径认证和知乎开放平台鉴权完全分离，不把第三方凭据绑定到用户 Session。
- 正式身份必须同时具有有效 Session 与已验证邮箱；验证成功不自动建立产品 Session。

## 密钥与日志

- 知乎 Access Secret、模型密钥和认证密钥只存在于服务端密钥配置中。
- 密钥不得进入客户端构建产物、HTTP/SSE 响应、数据库、测试快照或日志。
- 日志默认记录内部关联 ID、错误类别和阶段，不记录密码、令牌、完整第三方正文或模型敏感输入。
- 环境变量缺失时启动或相关功能应显式失败，不提供生产默认密钥。
- Resend API Key、邮箱验证 Token 和完整验证 URL 同样属于服务端敏感信息，不得进入客户端、日志或测试快照。

## 已实施的认证防护

- Better Auth 与 Drizzle 使用锁定版本，Session、验证状态和限流计数保存在 PostgreSQL；
- Session Cookie 为 `HttpOnly`、`SameSite=Lax`、`Path=/`，生产环境为 `Secure`，Cookie cache 关闭；
- Origin、CSRF 检查保持启用，可信 Origin 必须显式配置；
- 可信代理 IP/CIDR 必须显式验证并传给 Better Auth；部署网络必须阻止客户端绕过代理伪造转发地址；
- 身份模块只公开已验证的最小正式身份，不公开数据库记录、密码哈希、验证值或 Session Token；
- Resend 适配器直接调用 HTTP API，供应商正文收敛为稳定错误；Better Auth 的账户创建成功不代表邮件已送达，未验证账户只能通过显式重发恢复；
- 单元、契约、真实 PostgreSQL 集成和客户端依赖图测试覆盖上述边界。具体端点行为见[认证框架契约](../api/authentication.md)。

## 内容与模型

- 知乎内容和模型输出均视为不可信输入，进入领域前执行长度、类型、枚举、URL 和关系校验。
- 展示第三方内容时防止脚本注入；不直接信任外部 HTML。
- 模型提示和输出不得获得不需要的用户隐私、认证信息或内部密钥。
- 来源链接只能由知乎适配器提供，不接受模型生成链接。

## 题目、生成任务与报告

- 未作答题面 DTO 与含答案的服务端模型必须隔离，避免序列化时意外泄露答案。
- 判题、得分和完成状态只在服务端产生；幂等提交、最佳成绩和首次完成在同一事务中处理。
- 生成任务状态、SSE 和错误只允许 ADR-0014 定义的任务参与者读取。
- 自定义地图正文只允许具有对应学习关系的账户读取；缓存复用不能扩大资源权限。
- 结课报告 Route Handler 要求正式身份；目录与进度公开入口各自校验关系所有权，报告只投影固定地图版本、固定题目集、成绩、完成状态和不可变尝试涉及的安全元数据。
- 结课报告响应不包含用户资料、Session、答案、原始尝试数组或 `attemptId`；不存在和错误账户统一安全 `404`，且不得使用共享缓存。

## 后续能力实施前必须完成

- 明确请求体、主题输入、SSE 连接和生成频率限制；
- 建立持续依赖审计、密钥扫描和客户端包内容检查；
- 为未登录访问、任务参与关系、自定义地图越权、答案泄露和报告越权编写对应集成测试。
