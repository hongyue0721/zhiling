# 工作包与并行顺序

> 状态：分工骨架。负责人和代码目录在工程目录 ADR 接受后填写。

## 分工原则

- 以稳定业务边界或完整纵向能力分工，不以“随便切几个文件”分工；
- 每个工作包先明确输入契约、输出契约、数据所有权和验收测试；
- 同一内部文件若需要多人频繁修改，应先调整边界，而不是依靠口头协调；
- 公共契约变更由提供方提出，所有消费方共同评审；
- 代码、测试、API 契约、ADR 和使用文档由同一工作包同步交付。

## 当前阶段退出条件

开始工程基础工作前，至少需要：

1. 接受工程目录与依赖方向 ADR；
2. 接受地图生成状态机和发布原子性 ADR；
3. 取得知乎 API 真实契约并明确适配器输入输出；
4. 确认匿名账户合并的逐实体冲突规则；
5. 确认首版 HTTP 错误模型和 SSE 事件契约；
6. 确认目标部署环境是否支持所选任务与 SSE 运行方式。

## 工作包完成定义

- 验收标准逐项通过，并记录实际验证命令；
- 核心正常、边界和失败路径具有自动化测试；
- 未绕过模块公开契约访问内部数据；
- API、架构、运行和变更文档同步更新；
- 兼容行为已登记支持范围与移除条件；
- PR 由受影响模块所有者评审。
