# 产品需求索引

> 状态：目标基线已确认。完整产品事实和第一阶段边界以 [`PROJECT_GOAL.md`](../../PROJECT_GOAL.md) 为单一事实源；本文件用于需求拆分与追踪，不复制另一份可能漂移的产品定义。

## 产品目标

将知乎真实内容组织为具有先修关系的学习地图，让学习者能够查看来源、理解共识与分歧，并通过有来源依据的题目验证学习效果。

## 首期范围

| 能力 | 范围 | 验收依据 |
| --- | --- | --- |
| 首页 | 精选主题、自定义主题入口及两者的清晰区分 | 项目目标 4.1、成功标准 1 |
| 学习地图 | 5–7 个节点、先修关系、稳定交互和节点面板 | 项目目标 4.2 |

| 学习验证 | 每节点 2–3 道来源题、服务端判题和进度更新 | 项目目标 3.3、4.4 |
| 身份与进度 | 强制登录、邮箱账户、会话恢复及个人学习数据 | 项目目标 3.4、4.5 |
| 报告与分享 | 结课报告、登录后读取的只读快照和即时撤销 | 项目目标 4.6 |

第一阶段非目标完整列表见项目目标第 5 节，包括付费系统、社区、移动 App、全量抓取和开放式主观评分等。

## 核心业务流程

1. 未认证访问者完成注册或登录后进入产品。
2. 登录用户选择精选地图，完成来源阅读、答题和报告闭环。
3. 登录用户提交自定义主题，系统查询缓存或执行生成流水线，并通过 SSE 报告阶段状态。
4. 登录用户创建只读分享快照，并可撤销其他已登录用户的访问。

## 核心业务规则

- 结论与题目解释必须引用系统实际取得的来源，模型不得生成来源 URL。
- 来源不足必须明确失败或标记材料不足，不能用模型常识补齐。
- 节点完成由服务端答题结果驱动，不能由客户端任意标记。
- 正确答案不得随未作答题目发送给浏览器。
- 一张地图可由多个用户学习，地图内容与用户学习状态分离。
- 所有产品页面和业务接口必须具有统一登录门禁，只有认证相关入口允许未登录访问。
- 分享读取创建时的快照；撤销后访问必须立即失效。

## 验收标准

以项目目标第 10 节的十项成功标准为准。后续拆分为测试场景时，每项必须指定可观察结果、测试层级和负责人。

## 开放问题

1. 知乎开放 API 的正式接口、比赛接口、权限和速率限制具体契约是什么？
2. 模型供应商、结构化输出能力和失败重试约束是什么？
3. 节点完成的及格规则和最佳成绩冲突策略是什么？
4. 认证会话有效期和登录失败限制是什么；邮箱验证与密码恢复是否纳入一期？
5. 精选地图的审核、发布、版本更新与回退流程是什么？
6. 目标部署平台、运行区域、日志留存和隐私要求是什么？
